# 吉林鑫基矿业 · 矿石配送 ERP 部署文档

本文档面向**要把这套系统在本机跑起来验收**、或者**部署到矿区服务器**的开发和运维同学。
按顺序做完第一到第六章，系统就能跑；第七、八章是验收；第九章是上服务器。

---

## 一、部署前准备

### 1.1 软件要求

| 软件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | **1.8**（8u202 及以上） | 项目用 Java 8 编译，JDK 11/17 直接跑会因依赖版本报错 |
| Maven | 3.6+ | IDEA 自带即可，命令行部署需要 |
| MySQL | **8.0** | 用了 `utf8mb4` 和窗口函数外的常规语法，5.7 也能跑但不建议 |
| Redis | **5.0+**（推荐 6.x） | 用到 Stream（5.0 引入）和 Lua，Redis 4 以下不行 |
| IDE | IntelliJ IDEA 2021+ | 需要 Ultimate 才方便用 Database 面板，社区版可用命令行导库 |
| Memcached | 1.6+（**可选**） | 第三级缓存，默认关闭，不装不影响启动 |

### 1.2 端口占用

| 端口 | 用途 | 可否修改 |
| --- | --- | --- |
| 8080 | 应用 HTTP | 可以，改 `server.port` |
| 3306 | MySQL | 可以，改数据源 url |
| 6379 | Redis | 可以，改 `spring.redis.port` |
| 11211 | Memcached（可选） | 可以，改 `xinji.cache.memcached-port` |

启动前确认 8080 没被占用：

```bash
# Windows
netstat -ano | findstr :8080
# macOS / Linux
lsof -i:8080
```

## 二、搭建依赖环境

有两种方式，任选一种。**已有 MySQL/Redis 的机器直接看 2.1/2.2 的「已装」部分。**

### 2.1 方式 A：使用本机已有的 MySQL / Redis

**MySQL**

确认服务在跑，并能用账号登录：

```bash
mysql -uroot -p -e "SELECT VERSION();"
```

**Redis**

```bash
redis-cli ping
# 期望输出 PONG
```

如果 Redis 设了密码，后面配置里要补 `spring.redis.password`。

### 2.2 方式 B：用 Docker 一键起依赖

项目根目录已提供 `docker-compose.yml`：

```bash
cd xinji-erp
docker compose up -d          # 只起 MySQL + Redis
docker compose --profile cache up -d   # 连 Memcached 一起起
docker compose ps             # 确认三个容器 healthy
```

`docker-compose.yml` 里 MySQL 首次启动会**自动执行** `server/src/main/resources/db/` 下的建表与初始化脚本（已按 `01-schema.sql` / `02-data.sql` 顺序挂载），所以用 Docker 方式可以**跳过第三章**。

> 注意：只有在数据卷为空（首次启动）时才会执行初始化脚本。如果之前起过、要重新初始化，执行 `docker compose down -v` 再 `up`。

### 2.3 手动安装参考（Linux 服务器）

```bash
# MySQL 8.0（Ubuntu 示例）
sudo apt install -y mysql-server
sudo systemctl enable --now mysql
sudo mysql_secure_installation

# Redis
sudo apt install -y redis-server
sudo systemctl enable --now redis
# 建议给 Redis 设密码并只监听内网，生产环境不要暴露 6379
```

## 三、初始化数据库

### 3.1 命令行导入（推荐，最不容易出错）

在**项目根目录**执行：

```bash
# Windows 注意用 Git Bash 或 PowerShell，路径分隔符按自己环境调整
mysql -uroot -p --default-character-set=utf8mb4 < server/src/main/resources/db/schema.sql
mysql -uroot -p --default-character-set=utf8mb4 < server/src/main/resources/db/data.sql
```

- `schema.sql`：建库 `xinji_erp` + 21 张表，可重复执行（内部是 `DROP TABLE IF EXISTS` + `CREATE`）
- `data.sql`：灌入演示数据（5 个客户、6 个物料、8 张订单、秒杀活动、库存台账、6 台车 / 5 名司机 / 3 张派车单、3 张生产工单、2 条收款流水、2 张发票）

**一定要带 `--default-character-set=utf8mb4`**，否则 Windows 控制台会用 GBK 解析文件，中文物料名会变乱码。

### 3.2 用 IDEA 的 Database 面板导入

1. 右侧 `Database` → `+` → `Data Source` → `MySQL`
2. Host `127.0.0.1`，Port `3306`，User `root`，Password 填自己的，Database 留空
3. 首次连接会提示下载驱动，点 `Download`
4. 右键连接 → `Run SQL Script...` → 选 `schema.sql` → 执行
5. 同样方式执行 `data.sql`
6. 刷新后应该能看到 `xinji_erp` 库下的 21 张表

### 3.3 校验导入结果

```sql
USE xinji_erp;

SELECT COUNT(*) FROM t_sku;             -- 6
SELECT COUNT(*) FROM t_customer;        -- 5
SELECT COUNT(*) FROM t_order;           -- 8
SELECT COUNT(*) FROM t_seckill_sku;     -- 6

-- 双池恒等式：物理总库存 = 可售 + 活动划拨 + 冻结
SELECT sku_name, stock_qty, activity_alloc_qty, frozen_qty,
       stock_qty + activity_alloc_qty + frozen_qty AS physical_total
FROM t_sku;
```

期望 `physical_total` 依次为：3240 / 1860 / 620 / 480 / 1120 / 2400，合计 **9720 吨**。

## 四、配置文件说明

### 4.1 配置文件在哪里

**只有一个主配置文件**：`server/src/main/resources/application.yml`。

它用 `---` 分隔成了三段：

| 段 | 作用 |
| --- | --- |
| 第 1 段（无 profile 标记） | 通用配置：端口、Jackson、MyBatis-Plus、Swagger、业务参数 |
| 第 2 段 `on-profile: dev` | 本地开发：MySQL/Redis 写死本机地址 |
| 第 3 段 `on-profile: prod` | 生产：从环境变量读连接信息 |

默认激活 `dev`：

```yaml
spring:
  profiles:
    active: dev
```

### 4.2 必须按自己环境改的三处

| 位置 | 默认值 | 说明 |
| --- | --- | --- |
| `spring.datasource.username/password`（dev 段） | `root` / `1234` | 改成你本机的 MySQL 账号密码 |
| `spring.datasource.url`（dev 段） | `127.0.0.1:3306/xinji_erp` | 库名或端口不同就改这里 |
| `spring.redis.host/port/database`（dev 段） | `127.0.0.1:6379` / 库 `5` | 用 5 号库是为了不和本机其他项目冲突 |

### 4.3 完整配置项

```yaml
server:
  port: 8080                    # 应用端口
  servlet.encoding.charset: UTF-8   # 强制 UTF-8，避免中文乱码

spring:
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss  # 统一时间格式
    time-zone: Asia/Shanghai
    default-property-inclusion: non_null  # null 字段不输出，前端少判空
  mvc.pathmatch.matching-strategy: ant_path_matcher  # 兼容 springdoc

mybatis-plus:
  global-config.db-config:
    table-prefix: t_            # 实体类 Sku 自动映射 t_sku
    id-type: auto
  configuration:
    map-underscore-to-camel-case: true   # stock_qty -> stockQty

xinji:
  jwt:
    secret: xinji-mining-erp-jwt-secret-key-2026-change-in-prod  # ★生产必须换
    expire-minutes: 720         # token 有效期 12 小时
  cache:
    memcached-enabled: false    # 没有 memcached 就保持 false，不会影响启动
    memcached-host: 127.0.0.1
    memcached-port: 11211
    caffeine-max-size: 2000     # 本地缓存最大条目
    caffeine-ttl-seconds: 120   # 本地缓存 2 分钟
    redis-ttl-seconds: 600      # Redis 缓存 10 分钟
  seckill:
    stream-key: sk:stream:token # Redis Stream 键名
    group: sk-token-group       # 消费组
    consumer: consumer-1        # 消费者名，多实例部署时每个实例要唯一
    token-expire-minutes: 15    # 抢到令牌后多久没下单就释放库存
    auto-create-group: true     # 启动时自动建消费组
  order:
    min-qty: 1                  # 单笔起订量（吨）

logging:
  level:
    root: info
    com.xinji.erp: debug        # 想看 SQL 就保持 debug，prod 段已关掉
```

### 4.4 生产环境配置

`prod` 段全部走环境变量，**不用改代码**：

```bash
export MYSQL_HOST=10.0.1.20
export MYSQL_PORT=3306
export MYSQL_USER=xinji
export MYSQL_PASSWORD='改成强密码'
export REDIS_HOST=10.0.1.21
export REDIS_PORT=6379
export REDIS_PASSWORD='redis密码'
export REDIS_DB=0

java -jar xinji-erp.jar --spring.profiles.active=prod --server.port=8080
```

启动时用 `--spring.profiles.active=prod` 覆盖，或改 `application.yml` 里 `spring.profiles.active`。

> **强制要求**：生产必须替换 `xinji.jwt.secret`，用一个 32 位以上随机串。默认值写在代码库里，任何人都能伪造 token。

## 五、启动项目

### 5.1 方式 A：IntelliJ IDEA 运行（推荐用于验收）

1. **打开项目**
   `File` → `Open` → 选择 `xinji-erp/server/pom.xml` → `Open as Project`
   （不要选整个 `xinji-erp` 目录，那样 IDEA 认不出 Maven 工程）

2. **确认 JDK**
   `File` → `Project Structure` → `Project`：
   - `Project SDK` 选 **JDK 1.8**
   - `Language level` 选 **8**

3. **等依赖下载完**
   右下角进度条跑完。如果卡住，右键 `pom.xml` → `Maven` → `Reload Project`。
   国内网络慢可以配阿里云镜像：在 `~/.m2/settings.xml` 的 `<mirrors>` 里加
   ```xml
   <mirror>
     <id>aliyun</id>
     <mirrorOf>central</mirrorOf>
     <url>https://maven.aliyun.com/repository/public</url>
   </mirror>
   ```

4. **检查编码**
   `Settings` → `Editor` → `File Encodings`：三个都设成 **UTF-8**，勾选 `Transparent native-to-ascii conversion`。
   （否则启动日志和接口返回里的中文会乱码）

5. **运行**
   打开 `src/main/java/com/xinji/erp/ErpApplication.java`，点 `main` 方法左边的绿色三角 → `Run 'ErpApplication'`

6. **看启动日志**
   控制台出现下面这行就是成功了：
   ```
   Started ErpApplication in 5.3 seconds (JVM running for 6.1)
   ```

> 如果控制台提示 `Port 8080 was already in use`，说明端口被占。可以在 `Run/Debug Configurations` 的 `VM options` 里加 `-Dserver.port=8081`。

### 5.2 方式 B：命令行打包运行

```bash
cd server

# 打包（跳过测试，第一次会下载依赖，耐心等）
mvn clean package -DskipTests

# 运行
java -jar target/xinji-erp.jar

# 指定 profile 和端口
java -jar target/xinji-erp.jar --spring.profiles.active=prod --server.port=8080
```

如果报 `No compiler is provided in this environment. Perhaps you are running on a JRE rather than a JDK`，
说明 `JAVA_HOME` 指向了 JRE，改成 JDK 目录：

```bash
# Windows PowerShell
$env:JAVA_HOME='C:\Program Files\Java\jdk1.8.0_241'
$env:PATH=$env:JAVA_HOME+'\bin;'+$env:PATH
# macOS / Linux
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk1.8.0_241.jdk/Contents/Home
```

### 5.3 常见启动报错对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `Communications link failure` | MySQL 没起 / 地址端口错 | 启动 MySQL，核对 `datasource.url` |
| `Access denied for user 'root'@'localhost'` | 数据库密码不对 | 改 `application.yml` 里的 password |
| `Unknown database 'xinji_erp'` | 没导 `schema.sql` | 回到第三章导入 |
| `Unable to connect to Redis` | Redis 没起 | 启动 Redis，`redis-cli ping` 验证 |
| `NOGROUP No such key`（日志告警） | 消费组还没建 | 正常现象，程序启动时会自动创建，或手动调一次预热接口 |
| `Port 8080 was already in use` | 端口占用 | 换端口 `--server.port=8081` |
| 中文全部变成 `??` 或乱码 | 数据库连接没带 `characterEncoding=utf8` | 检查 url 参数，或重导数据时加 `--default-character-set=utf8mb4` |

## 七、业务验收（对照原型页面看）

打开 `prototype/index.html` 可以看到三端原型和技术架构说明。下面按业务顺序验收，
每一步都给了接口和**预期结果**。

### 7.1 三端隔离 —— 客户碰不到后台

这是客户最关心的一条：运营后台不能暴露给客户。

```bash
# 用客户 token 访问后台接口
curl http://127.0.0.1:8080/api/admin/orders \
  -H "Authorization: Bearer <客户token>"
# 预期：{"code":403,"msg":"无权限访问管理后台接口"}

# 不带 token
curl http://127.0.0.1:8080/api/admin/orders
# 预期：{"code":401,"msg":"缺少登录凭证，请先登录"}
```

原型上 `admin.html` 也有登录门禁：不登录只能看到登录卡片，侧边栏和工作台都不渲染。

### 7.2 商品与双池

```bash
curl http://127.0.0.1:8080/api/client/products -H "Authorization: Bearer <客户token>"
```

预期第一个物料「石灰石 5-10mm」：

```
saleableQty: 2344   activityAllocQty: 800   frozenQty: 96   totalQty: 3240
```

三个池子加起来等于物理总库存 3240 吨 —— 这就是双池模型，验收时重点看这个恒等式。

### 7.3 下单到签收的完整链路

| 步骤 | 接口 | 预期 |
| --- | --- | --- |
| ① 下单 30 吨 | `POST /api/client/orders` | 返回订单号，`saleableQty 2344→2314`、`frozenQty 96→126`、**总库存仍 3240** |
| ② 超量下单 99999 吨 | 同上 | `{"code":500,"msg":"可售库存不足，当前可售 2314 吨…"}` |
| ③ 审核 | `POST /api/admin/orders/{单号}/audit` | `code=0`，状态 `PENDING_AUDIT→AUDITED` |
| ④ 派车 | `POST /api/admin/orders/{单号}/dispatch` | 状态 `→DISPATCHED` |
| ⑤ 出厂 | `POST /api/admin/orders/{单号}/ship` | `frozenQty 126→96`，**总库存 3240→3210**（货走了） |
| ⑥ 过磅 | `POST /api/admin/weigh/tickets` | 见下方计算 |
| ⑦ 签收 | `POST /api/admin/orders/{单号}/sign` | 状态 `→SIGNED` |

**过磅计算校验**（毛重 52.400、皮重 17.200、含水率 1.1%、扣杂 0.15）：

```
净重   = 52.400 - 17.200            = 35.200 吨
扣水量 = 35.200 × 0.011             =  0.387 吨
结算量 = 35.200 - 0.387 - 0.150     = 34.663 吨
结算金额 = 34.663 × 86.00           = 2981.02 元
```

出完票后查订单详情，明细里的 `settleQty / settleAmount` 应该已经变成 34.663 / 2981.02 ——
财务后面就按这个数收钱，不再二次计算，避免和客户扯皮。

### 7.4 采购到货入库

| 步骤 | 接口 | 预期 |
| --- | --- | --- |
| 建单 | `POST /api/admin/purchase/orders` | 状态 `PENDING` |
| 到货登记 120 吨 | `POST /api/admin/purchase/orders/{id}/arrive` | 状态 `PARTIAL`，`arrivedAmount = 120×58 = 6960` |
| 查台账 | `GET /api/admin/stock/flows?skuId=2` | 一条 `INBOUND 120 吨`，`beforeQty 1160 → afterQty 1280` |

采购入库不直接改库存表，而是走 `StockService.inbound`，保证台账和库存永远一致。

### 7.5 对账与收款

| 步骤 | 接口 | 预期 |
| --- | --- | --- |
| 生成对账批次 | `POST /api/admin/finance/settlements`（客户 2，账期 2026-11-01） | 把该客户账期内所有 `SIGNED` 订单收进批次，订单状态自动变 `SETTLED` |
| 查明细 | `GET /api/admin/finance/settlements/{id}/items` | 列出每张订单的结算吨数和金额 |
| 确认对账 | `POST /api/admin/finance/settlements/{id}/confirm` | 批次 `DRAFT→CONFIRMED`，同时生成一条应收 `UNPAID` |
| 收款 2000 元 | `POST /api/admin/finance/receivables/{id}/receive?amount=2000` | 状态变 `PARTIAL` |
| 再收超额 | 同上 `amount=999999` | `{"code":500,"msg":"收款金额超过应收金额…"}` |

同一张订单**不会被重复对账**：`t_settlement_item` 上有 `uk_order` 唯一索引兜底。

### 7.6 秒杀

| 步骤 | 接口 | 预期 |
| --- | --- | --- |
| 预热 | `POST /api/admin/seckill/activities/1/warmup` | 把活动库存写进 Redis，恢复已抢用户集合 |
| 看活动 SKU | `GET /api/client/seckill/activities/1/skus` | `石灰石5-10`：活动量 800、已抢 536、剩余 264、销售可售 2314（两个池子独立显示） |
| 抢 20 吨 | `POST /api/client/seckill/grab` | `success=true`，`remainStock=244`，返回令牌号 |
| 再抢一次 | 同上 | `success=false`，`reason="每人限抢一份，你已经抢到过了"` |
| 查令牌 | `GET /api/client/seckill/tokens/{令牌号}` | 约 1~2 秒后状态变 `ISSUED`（Redis Stream 异步落库的结果） |
| 令牌下单 | `POST /api/client/seckill/tokens/{令牌号}/order` | 生成 `SECKILL` 订单，活动价 72 元/吨，订单金额 1440 |
| 校验双池 | `GET /api/client/products` | `activityAllocQty 800→780`，**`saleableQty 2314 不变** |
| 令牌重复用 | 再用一次下单接口 | `{"code":500,"msg":"令牌状态为「USED」，无法下单"}` |

> 令牌 15 分钟不兑换会自动过期：定时任务把令牌置 `EXPIRED`、活动库存归还 Redis 和数据库、从已抢集合里移除该用户，客户可以重新抢。

### 7.7 库存台账

```bash
curl "http://127.0.0.1:8080/api/admin/stock/flows?page=1&size=20" -H "Authorization: Bearer <后台token>"
```

每一条都带 `beforeQty / afterQty`，能逐笔倒推。业务类型：

| bizType | 含义 | 对三个池子的影响 |
| --- | --- | --- |
| `INBOUND` | 采购入库 | 可售 ↑，物理总量 ↑ |
| `ALLOC` | 划拨到活动池 | 可售 ↓，活动 ↑，总量不变 |
| `RETURN` | 活动剩余量回拨 | 可售 ↑，活动 ↓，总量不变 |
| `FREEZE` | 下单冻结 | 可售 ↓，冻结 ↑，总量不变 |
| `UNFREEZE` | 取消订单解冻 | 可售 ↑，冻结 ↓，总量不变 |
| `OUTBOUND` | 出厂核销 | 冻结 ↓，物理总量 ↓ |

### 7.8 后台工作台

```bash
curl http://127.0.0.1:8080/api/admin/dashboard/summary -H "Authorization: Bearer <后台token>"
```

返回订单总数、各状态分布、可售总量、活动划拨总量、物理总库存、应收未收，以及库存预警列表
（只列可售量低于安全库存的物料）。

## 十、常见问题 FAQ

**Q1：启动后接口返回中文是乱码？**

三个地方要一起确认：
1. 数据库连接 url 带 `characterEncoding=utf8`
2. 导数据时加了 `--default-character-set=utf8mb4`
3. IDEA 的 `File Encodings` 全设成 UTF-8

**Q2：控制台日志里中文乱码，但接口返回正常？**

这是 Windows 控制台代码页（GBK）的问题，不影响业务。可以执行 `chcp 65001` 切到 UTF-8，
或在 IDEA 的 `Run/Debug Configurations` 里给 VM options 加 `-Dfile.encoding=UTF-8`。

**Q3：抢购接口报「活动库存尚未预热」？**

Lua 脚本在 Redis 里找不到库存 key。在后台调一次
`POST /api/admin/seckill/activities/1/warmup` 即可。生产环境建议活动开始前 10 分钟自动预热。

**Q4：抢到了但订单一直没生成？**

令牌是**异步发放**的，正常 1~2 秒内到位（查 `GET /api/client/seckill/tokens/{令牌号}` 看状态）。
超过 10 秒还是 `PENDING`，看后台监控接口：

```bash
curl http://127.0.0.1:8080/api/admin/seckill/monitor -H "Authorization: Bearer <后台token>"
# pendingCount 是 pending-list 里待补偿的条数
```

程序每 30 秒会 `XCLAIM` 一次 pending-list 做补偿，一般能自愈。

> **补充**：如果刚好清过 Redis（`FLUSHDB`）或 Redis 重启过，消费者组会一起消失，
> 表现为「抢购成功但令牌一直 404」。程序每 10 秒探一次消费者组、每 3 秒兜底拉一次未投递消息，
> 组丢失会自动重建并从 0 重放（重放靠 `t_seckill_token` 唯一索引幂等，不会重复发券），
> 最长几秒恢复，不需要重启应用。

**Q5：改了库存但页面还是旧数字？**

三级缓存的问题。库存变动后代码会清缓存，而且是在**事务提交后**清（避免并发读到未提交数据再回填）。
如果还是旧的，检查是不是直接改的数据库 —— 绕过服务改库不会触发清缓存，需要重启或等 TTL 到期（本地 2 分钟 / Redis 10 分钟）。

**Q6：`mvn` 提示 `No compiler is provided`？**

`JAVA_HOME` 指到了 JRE。改成 JDK 目录，见 5.2 节。

**Q7：想启用 Memcached 第三级缓存？**

```bash
docker compose --profile cache up -d memcached
```
然后改 `application.yml`：`xinji.cache.memcached-enabled: true`，重启应用。
装不上也不影响，前两级（Caffeine + Redis）已经够用。

**Q8：端口改不了 / 启动读到的是别的端口？**

检查有没有环境变量 `SERVER_PORT` / `SERVER__PORT`，Spring Boot 会优先读环境变量。
临时指定：`java -jar xinji-erp.jar --server.port=8081`。

**Q9：接口传时间报 `JSON parse error: Cannot deserialize LocalDateTime`？**

已做全局兼容（`config/JacksonConfig`），`2026-11-03 07:30:00` 和 `2026-11-03T07:30:00`
两种写法都能接收。如果自己新加了 DTO 且用了 `java.util.Date`，建议统一换成 `LocalDateTime`。

**Q10：调接口报 400 且返回体是空的？**

多半是 URL 里带了中文没编码，Tomcat 会直接拒掉请求。用 `--data-urlencode` 编码，
或改用 body 传参（例如收款流水用 `POST /api/admin/finance/receivables/{id}/receive-detail` 时对 `remark` 编码）。

**Q11：生产完工后库存翻倍 / 对不上？**

检查是不是漏了「完工只调一次」这条 —— 重复报产会被状态机拦住（`已完工，不能重复报产`）。
如果确实多入了一次，不要直接改 `t_sku`，补一条反向的 `INBOUND` 负数台账（盘点单），保证台账可追溯。

### 11.4 压测建议

抢购是唯一的高并发接口，压测重点：

```bash
# 准备 500 个客户 token，压 200 并发
wrk -t8 -c200 -d30s -s grab.lua http://127.0.0.1:8080/api/client/seckill/grab
```

关注三个指标：

1. **有没有超卖**：`SELECT activity_stock, sold_qty FROM t_seckill_sku` 中 `sold_qty` 不能超过 `activity_stock`
2. **令牌数对不对**：`SELECT COUNT(*) FROM t_seckill_token WHERE status='ISSUED'` 应该等于实际抢到的数量
3. **Redis Stream 积压**：`monitor` 接口的 `pendingCount` 应该很快回落到 0
