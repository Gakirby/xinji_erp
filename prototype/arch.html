技术架构 · 限时抢购链路

订单与库存的高并发入口，难点不在“能抢”，而在“抢不超卖、发不重复、挂了能补”。核心思路是把一次抢购拆成两段：Redis 内一次 Lua 脚本完成资格判断与库存扣减并落消息，接口立刻返回订单号；真正的落库、凭证发放交给 Stream 消费者组异步完成，用补偿兜住异常。

抢购原子脚本

一次网络往返完成四件事
-- 资格 + 库存 + 一人一单 + 写 Stream，全部在 Redis 内原子完成 local stockKey = KEYS[1] -- sk:stock:{skuId} local userKey = KEYS[2] -- sk:user:{skuId} local stream = KEYS[3] -- sk:stream:order local uid = ARGV[1] local qty = tonumber(ARGV[2]) local oid = ARGV[3] if redis.call('SISMEMBER', userKey, uid) == 1 then return -1 -- 重复抢购 end local stock = tonumber(redis.call('GET', stockKey) or '-1') if stock < qty then return -2 -- 库存不足 end redis.call('DECRBY', stockKey, qty) redis.call('SADD', userKey, uid) redis.call('XADD', stream, '*', 'uid', uid, 'qty', qty, 'oid', oid) return stock - qty -- 剩余库存

消费端幂等

重复消费 / 重启 / 并发三重兜底
// 用户维度锁 + 条件扣减 + 唯一索引，任意一层都能拦住重复发放 RLock lock = redisson.getLock( "lock:order:" + uid + ":" + skuId); lock.tryLock(3, TimeUnit.SECONDS); try { // update stock set stock = stock - #{qty} where id = ? and stock >= #{qty} int rows = stockMapper.deduct(skuId, qty); if (rows == 0) return; // 已售罄，幂等退出 orderMapper.insert(order); // uk(user_id, sku_id) 兜底 ledgerMapper.insert(ledger); // 提货凭证账本 stream.ack("sk-order-group", msgId); // 确认消费 } finally { lock.unlock(); }
三重幂等：① Redisson 用户维度锁，把同一用户的并发请求串行化；② where stock >= #{qty} 条件扣减，数据库层兜住超卖；③ uk(user_id, sku_id) 唯一索引，兜住重复消费与服务重启后的重放。

binlog 驱动的缓存同步

业务事务内不做多层双写
// 业务只写 MySQL，缓存由订阅端按数据类型分别处理 @Subscribe("canal.topic.sku") public void onSkuChange(SkuBinlogEvent e) { if (e.isDetail()) { // 详情类：主动同步到 Memcache，避免穿透 memcache.set("sku:" + e.getId(), e.getAfter(), 1800); } else { // 聚合类：删除失效，等下次读回填 redis.del("agg:sku:" + e.getId()); } // 广播 JVM 本地缓存失效事件，避免各实例数据不一致 cacheBus.publish("invalidate:sku:" + e.getId()); }

多级缓存回填

下层命中即回填上层
// 同一请求内重复读 SKU 上下文，直接命中请求级缓存 public SkuVO getSku(Long id) { return scope.get("sku:" + id, () -> // L1 请求内 jvm.get(id, () -> // L2 JVM memcache.get(id, () -> // L3 跨实例 redis.get(id, () -> // L4 共享 loadFromDb(id) // 回源 )))); }
每一层命中都会把结果回填到上层，一次抢购请求内部原本要读 6 次 SKU 与活动配置，实际只剩 1 次回源。
缓存穿透 不存在的数据

对查不到的 SKU 写入空值缓存并设置 60 秒短 TTL，配合参数校验与布隆过滤，避免请求全部打到 MySQL。

空值缓存 + 布隆过滤
缓存击穿 热点 key 过期

热点凭证包详情采用逻辑过期：过期后不阻塞读，先返回旧值，再由后台线程拿互斥锁重建，保证抢购瞬间不雪崩。

逻辑过期 + 互斥锁重建
缓存雪崩 大批同时失效

TTL 加 30—60 秒随机抖动，四级缓存层层兜底，叠加接口限流与售罄降级，把峰值压力挡在 Redis 之前。
